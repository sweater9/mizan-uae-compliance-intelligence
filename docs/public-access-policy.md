# Public free-access policy

Mizan's live AI assistant is free for everyone for one calendar month from launch.
No sign-in, email allowlist, payment card, or subscription is required.
There is one shared launch window, not a separate month for each visitor.

At the end of the month, live AI requests pause. Visitors are not charged or
automatically subscribed. The demo's static information and calculators remain
accessible. Any later paid offer requires a separate decision and implementation.

## Launch and enforcement

- Set `PUBLIC_TRIAL_START_AT` once, at launch, on each backend serving this app.
  Use a UTC ISO timestamp generated by `new Date().toISOString()`.
- Keep the same value across instances, redeployments, and hosting providers.
  Do not generate it at process startup, build time, or on a visitor's first request.
- The end is one calendar month later in UTC, preserving the time of day and
  clamping month-end dates to the last valid day of the next month.
- Both `app/api/assistant/route.ts` and `worker/index.ts` check the window before
  processing a question or contacting NVIDIA. Start is inclusive; end is exclusive.
- Missing or invalid configuration returns 503; before launch returns 403;
  after expiry returns 410. No upstream AI call is made in these cases.
- `GET /api/assistant` returns public policy status and dates with `no-store`.
  The assistant UI displays this status; the backend remains authoritative.
- Public hosting access must also be enabled. App-level anonymous access does
  not override a hosting platform's sign-in or workspace restrictions.

For Render, set the timestamp in the service's environment. For Cloudflare,
set it as a Worker variable. For Sites, set it through Sites runtime variables.
It is non-secret and must be identical on every active backend. Do not merge or
deploy the enforcement change without scheduling/configuring the launch value:
unconfigured live AI access deliberately fails closed.

## Credentials and cost

`NVIDIA_API_KEY` remains a server-side secret. Free access means free to visitors;
the operator remains responsible for provider and hosting usage.

This change enforces trial expiry and preserves the existing 4,000-character
question limit and 700-token output limit. It does not implement rate limiting,
a shared daily usage cap, bot detection, or sign-in. Those controls should be
configured separately before a broad public launch; the calendar window is not
a spending cap. An optional sign-in method could support higher per-user quotas
without removing anonymous access.

## Verification

Run `node --test tests/public-trial.test.mjs` with Node 22.13 or later.
Tests exercise the actual assistant handlers with NVIDIA mocked; no real keys
or paid requests are needed. They cover anonymous access, expiry, invalid
configuration, calendar boundaries, status metadata, and upstream-only keys.
